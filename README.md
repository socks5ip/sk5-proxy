## 一、SK5 到底是什么：一次正名

**SK5 = SOCKS5。**

这个词的来历很简单：`socks5` 连读时的发音接近「sock-five」，国内市场为了口语和省字数，直接写成了 SK5。你在百度、淘宝、各种代理商页面上看到的「SK5 代理」「SK5 独享 IP」「SK5 静态 IP」，指的都是 **SOCKS5 协议的代理服务**。

技术上一个字的差别都没有：

| 项目 | SK5 | SOCKS5 |
|---|---|---|
| 协议标准 | RFC 1928 | RFC 1928 |
| 默认端口 | 1080 | 1080 |
| 认证方式 | 无认证 / 用户名密码 | 无认证 / 用户名密码 |
| 支持 TCP | 是 | 是 |
| 支持 UDP | 是（RFC 1928 定义） | 是 |
| 客户端配置项 | 完全相同 | 完全相同 |

**这意味着两件实际影响钱的事：**

**第一，不要为「SK5」这个标签付溢价。** 有商家把「支持 SK5」当成卖点加价，其实所有支持 SOCKS5 的平台天然支持 SK5。我们实测的 24 家，**24 家全部提供 SOCKS5 出口**，也就是说这 24 家无一例外都「支持 SK5」。

**第二，排查故障时不要搜「SK5 教程」。** SK5 不是标准术语，搜出来的内容质量参差；搜「SOCKS5 配置」能拿到的文档、官方说明、排错路径都更完整。

### 三个常见误解

**误解 1：SK5 比 SOCKS5 更安全。**
不成立。同一协议、同一端口、同一认证方式，安全性完全取决于隧道是否加密（SOCKS5 本身不加密，加密靠上层 TLS/SSH）。

**误解 2：SK5 是 SOCKS5 的「升级版」。**
不成立。没有 SK6、SK4 这种东西。SOCKS4 也真实存在（不支持 UDP 和 IPv6），SOCKS5 是它的下一版，SK5 只是 SOCKS5 的别名。

**误解 3：SK5 只能配软路由。**
不成立。SK5/SOCKS5 是通用协议，Windows、macOS、安卓、iOS、软路由、浏览器插件都能配。第 4 节给了四种最常见客户端的配置要点。

## 二、五种代理协议对照（别买错）

选平台前先确认你要的协议。下表把国内平台常见的五种协议放在一起对比：

| 维度 | SOCKS5（SK5） | HTTP / HTTPS | L2TP | PPTP | SS / SSR |
|---|---|---|---|---|---|
| 工作层级 | 会话层（TCP/UDP 转发） | 应用层 | 网络层（VPN 隧道） | 网络层（VPN 隧道） | 自定义加密协议 |
| 是否加密 | 不加密（可套 TLS） | 不加密 | 有（IPSec） | 弱加密（已不安全） | 有 |
| 配置难度 | 低（填地址端口账号） | 最低 | 中（需系统 VPN 设置） | 低 | 中（需专用客户端） |
| 应用兼容性 | 最广，几乎全场景 | 仅 HTTP 流量 | 系统级全局 | 系统级全局 | 需客户端支持 |
| 支持 UDP | 是 | 否 | 是 | 是 | 是 |
| 典型用途 | 浏览器、采集、多开软件 | 浏览器、爬虫 | 全局代理、游戏 | 老设备兼容 | 个人翻墙（非商用） |
| 国内平台支持率 | **24 / 24** | 22/24（92%） | 15/24（62%） | 5/24（21%） | 极少商用提供 |
| 适合买 IP 业务的场景 | 绝大多数 | 纯网页采集 | 需要全局、需要游戏 | 老设备只能选它 | 不建议用于业务 |

**三条实用结论：**

1. **优先选 SOCKS5。** 24 家全覆盖，配置最简单，兼容性最好。绝大多数代理 IP 业务场景 SOCKS5 就够了。
2. **要全局代理才考虑 L2TP。** SOCKS5 是应用级，只有配置了代理的软件才走代理；L2TP 是系统级全局，但会拖慢整机网络，且部分平台对 L2TP 单独计价。
3. **PPTP 已经不安全了，能用别的就别用。** 协议本身有已知缺陷，只有老设备（部分老路由器、老工业设备）不得不选。

## 四、4 种客户端配置：Windows / 安卓 / 软路由 / 爱快

配置 SK5（SOCKS5）只需要四个参数：**服务器地址、端口、用户名、密码**。平台后台都能看到。下面按使用频率排序。

### 1. Windows：系统代理或专用客户端

**方式 A —— 系统级（最简单）**
`设置 → 网络和 Internet → 代理 → 手动设置代理`，填地址和端口。注意：Windows 系统代理**只对识别系统代理的软件生效**，部分客户端会绕过。

**方式 B —— 全局（推荐用于多账号业务）**
用支持 SOCKS5 的全局代理客户端（Proxifier 一类），把指定进程的流量强制走代理。这种方式能做到「只有目标软件走代理、其他软件走本地」，对账号环境隔离最友好。

**Windows 上最常见的坑**：系统代理不生效，是因为软件用的不是 WinINet 通道。判断方法——浏览器能通、但目标软件不通，就是这个问题，改用方式 B。

### 2. 安卓：WiFi 代理或分应用代理

**方式 A —— WiFi 代理**
长按已连接的 WiFi → 修改网络 → 高级选项 → 代理选「手动」→ 填主机名和端口。这种方式的限制是：**只对 WiFi 生效，切到移动数据就失效**；且部分 App 不读系统 WiFi 代理。

**方式 B —— 分应用代理**
用支持 SOCKS5 的本地代理客户端，按应用分流。适合「一个手机跑多个业务 App、每个 App 走不同 IP」的场景。

**安卓上最常见的坑**：填完 WiFi 代理后浏览器能上网、但目标 App 提示网络异常——通常是该 App 走了自己的网络栈。改用方式 B 分应用代理。

### 3. 软路由：全局透明代理

软路由（OpenWrt / iKuai / RouterOS）配 SOCKS5 一般是「透明代理」模式，让局域网内所有设备自动走代理，不用逐台配置。

配置思路：

1. 在软路由上装支持 SOCKS5 转发或透明代理的插件
2. 填入平台给的地址、端口、账号密码
3. 设置分流规则（国内直连、特定域名走代理）
4. 在客户端设备上把网关指向软路由

**软路由上最常见的坑**：DNS 没跟着走代理，导致「网页能开但登录提示地区不符」。SK5 只转发 TCP/UDP，DNS 需要单独配置转发，否则就是 DNS 泄漏。这一项在 [IP纯净度检测指南](https://github.com/socks5ip/ip-cleanliness-check) 第 4 步有专门的检查方法。

### 4. 爱快（iKuai）：多线分流与 IP 写入

爱快在游戏工作室和多账号场景用得多，它的特点是支持**多 WAN + 分流规则**，可以把不同内网设备绑到不同出口。

配置要点：

1. 在「网络设置 → 内外网设置」配置好 WAN
2. 在「流控分流 → 分流设置」按源 IP 或域名设置分流规则
3. 若用 SK5 作为出口，需要通过支持 SOCKS5 的插件或转换工具把 SK5 转成可路由的出口
4. 每台设备绑定固定出口，避免 IP 漂移导致账号关联

**爱快上最常见的坑**：把 SK5 当成可以直接填进 WAN 的协议。SK5 不是网络层协议，爱快原生 WAN 不直接支持，需要中间转换层。这一点商家页面基本不说明，是新手最容易卡住的地方。

## 五、SK5 和 SS / SSR / V2Ray 别混为一谈

这四个词经常被混着搜，但用途完全不同：

| 对比项 | SK5 / SOCKS5 | SS / SSR | V2Ray / Xray |
|---|---|---|---|
| 本质 | 标准代理协议（RFC 1928） | 加密代理工具（自带协议+混淆） | 代理平台框架（多协议支持） |
| 是否有标准 | 有，国际标准 | 无，个人项目定义 | 部分协议有标准 |
| 典型用途 | **商业 IP 业务**、采集、多账号 | 个人科学上网 | 个人科学上网、自建节点 |
| 商用 IP 平台是否提供 | **提供，24/24** | 极少 | 极少 |
| 计费方式 | 按 IP 数 / 按带宽 / 按月 | 多为自建或订阅 | 多为自建或订阅 |
| 是否适合做业务出口 | 适合 | 不适合（无 SLA、IP 共享严重） | 不适合（同上） |

**关键区别一句话**：SK5 是**买 IP 资源**用的协议，SS/V2Ray 是**自建通道**用的工具。拿 SS 机场的出口去做电商养号，IP 共享程度极高，是账号关联的高发原因。

## 六、5 个最常见的配置错误

**错误 1：把端口填成 HTTP 端口。**
同一平台常常 SOCKS5 和 HTTP 用不同端口（例如 SOCKS5 是 4xxxx、HTTP 是 3xxxx）。填错端口的表现是「连接被拒绝」或「能连上但不通」。**核对方法**：平台后台的端口列表里，SOCKS5 那一行才是要填的。

**错误 2：账号密码里的特殊字符没转义。**
如果密码含 `@`、`:`、`#` 这类字符，在 URL 形式的代理串里需要转义，否则会被解析成地址的一部分。表现是「认证失败」但密码明明是对的。**解决**：改用分字段填写（地址/端口/账号/密码分开），不要用一行 URL。

**错误 3：只配了代理，没配 DNS。**
SK5 转发流量但不接管 DNS。DNS 还在走本地运营商时，目标网站能看出你的真实位置。这是「IP 换了但还是被识别」的最常见原因。

**错误 4：在同一个 IP 上并发跑多个账号。**
这不是配置错误，是用错了。一条 IP 同时登录 5 个账号，是关联封号的头号触发条件。多账号业务必须要**一账号一 IP**，或者至少做到「同一时段同 IP 只有一号在线」。

**错误 5：用免费或极低价的共享池做长期业务。**
共享池的 IP 被几十上百人同时使用，纯净度评分普遍偏低，且随时可能被拉黑。短期测试可以用，长期业务不建议。

## 七、常见问题（10组问答）

**Q1：SK5 和 SOCKS5 到底是不是一回事？**
是。SK5 是国内对 SOCKS5 的口语化简称（socks5 连读接近「sock-five」），协议标准、端口、认证方式完全相同，没有任何技术差异。商家页面写「SK5」时，实际卖的就是 SOCKS5 代理。

**Q2：为什么有的平台只写 SK5 不写 SOCKS5？**
营销习惯。国内部分用户更熟悉「SK5」这个写法，平台为了匹配搜索词会这样标注。技术上是同一个东西。判断方法：看端口（默认 1080 或平台自定义）和配置项，与 SOCKS5 完全一致。

**Q3：SK5 支持 UDP 吗？**
支持。SOCKS5 协议（RFC 1928）本身定义了 UDP ASSOCIATE 命令。但实际是否可用取决于平台服务端是否开启 UDP 转发——部分平台只开 TCP。有 UDP 需求（如某些游戏、语音）要先问平台客服确认。

**Q4：SK5 会加密吗？**
不会。SOCKS5 本身不加密，只做转发。如果需要加密，要在上层套 TLS 或用 SSH 隧道。这一点和 SS/V2Ray 有本质区别。

**Q5：买了支持 SK5 的 IP，怎么确认真的能用？**
三步：① 用客户端连上，访问一个显示 IP 的网站，确认出口 IP 与购买的一致；② 查这条 IP 的 ASN 归属，确认是 ISP 而非机房；③ 做 DNS 和 WebRTC 泄漏检查。完整 9 项判定卡见 [IP纯净度检测指南](https://github.com/socks5ip/ip-cleanliness-check)。

**Q6：软路由配 SK5 要不要额外插件？**
要。SK5 是应用层协议，软路由原生不直接支持把它填进 WAN 口，需要支持 SOCKS5 转发的插件或透明代理组件做中间层。这是新手最容易卡住的一步。

**Q7：安卓手机配置 SK5 后，为什么有的 App 不走代理？**
因为安卓的 WiFi 代理只对读取系统代理设置的 App 生效，很多 App 走自己的网络栈。解决办法是用支持 SOCKS5 的本地分应用代理客户端，按应用分流。

**Q8：同一个 SK5 出口能同时给几台设备用？**
技术上不限制，但**业务上强烈不建议**。同一 IP 多设备并发登录，在风控侧表现为「同 IP 多账号」，是关联判定最直接的证据。多账号业务应做到一设备（或一账号）一 IP。

**Q9：SK5 和 L2TP 哪个快？**
不能一概而论。SOCKS5 是应用级转发，开销小，通常延迟更低；L2TP 是 VPN 隧道，加密与封装有额外开销，但它是系统级全局。实际速度更取决于线路质量和平台带宽档位，而不是协议本身。

**Q10：24 家平台都支持 SK5，那我该怎么选？**
先按业务定协议（多数情况 SOCKS5 就够），再按这几项筛：IP 类型（住宅还是机房）、地区覆盖是否含你要的城市、独享还是共享、带宽档位、是否支持当天换 IP。价格不是首要因素——2.24 元和 20 元的差异主要来自带宽与 IP 稀缺性，不直接等于纯净度差异。
